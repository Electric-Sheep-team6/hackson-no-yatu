## 3. 唯一のブロッカー: FFmpegバイナリがVercelに同梱されない

### 症状

デプロイ後の `/api/health` が返す値:
```
{"ok":false, ... ,"ffmpeg":{"available":false,"path":null},"supabase":{"connected":true}}
```
Supabaseは繋がっているので関数自体は正常。**FFmpegだけ見つからない。**

### 原因

- ビルド時にはバイナリが存在する（ビルドログに `ffmpeg is installed already.`）
- しかしコードはFFmpegを `import` していない。パス文字列で実行しているだけ
- Next.jsのfile tracingは `import` を辿って梱包対象を決めるため、**バイナリの必要性に
  気づけず梱包から漏れる**

### この状態の意味

**デプロイ済みサイトで「映画を生成」を押しても、シーン生成の直後にクロップ処理が
落ちて `failed` になる。動画は1本も完成しない。**

### 試して失敗した設定（3回とも `available:false`）

1. `outputFileTracingIncludes: { "/api/movies": ["./node_modules/ffmpeg-static/ffmpeg"] }`
2. `{ "/*": ["./node_modules/ffmpeg-static/**"] }`
3. `{ "/**": [...], "/api/movies": [...], "/api/health": [...] }`

また `vercel.json` に
`{"installCommand": "npm install && node node_modules/ffmpeg-static/install.js"}` を設定済み。
これでビルド時にバイナリがある状態にはなっている。

参考: ビルドログに npm の警告が出ている（新しいnpmのポリシー）。
```
npm warn allow-scripts ffmpeg-static@5.3.0 (install: node install.js)
npm warn allow-scripts Run npm approve-scripts <pkg> to allow.
```
ローカルnpmは 11.12.1 で `approve-scripts` が無い。Vercel側はより新しい。

### 【決定】採用する解決策

**ユーザー決定: `ffmpeg-static` のダウンロードに頼らず、FFmpegバイナリをリポジトリ内に
直接コミットする。** 日本語フォントも同じ扱いにする。

理由: tracingの挙動に依存せず、ビルド時のダウンロードにも依存しない。最も失敗しにくい。

実装時の注意:
- **linux x64 用のバイナリ**を置くこと（macOS用では動かない。Vercelはlinux）
- 実行権限が必要（`chmod +x`、gitのfile modeも保持されるか確認）
- `resolveFfmpegPath()` の候補順にこのパスを先頭側で追加する
- それでも `outputFileTracingIncludes` への明示は必要になる可能性が高い。
  値側は**ディレクトリ名ではなく実ファイルまで拾うglob**（`/**/*`）にすること
  （ChatGPTが指摘していた点。未検証）
- バイナリのサイズが大きい（数十MB）。Vercelのデプロイサイズ上限に注意

## 4. 【決定済み】予告編編集の仕様

**Geminiに予告編を作らせるのではなく、生成後にFFmpegで編集する。**
理由: omniは単一連続ショットしか作れない。文字描画は不安定。再生成は33秒＋課金。
編集はコードで決定論的に行うべき。

### 出力の前提（すべて確定）

- ホログラムファン表示機にTFカードで渡す。**スピーカーは無い。音声は不要**
- **黒＝消灯＝透明に見える。背景は純黒。これを明示的に前提として実装する**
- **実機確認済み: 正方形の動画が円形に切り取られて投影される**
- 出力: **720×720 / 24fps / 音声なし**
- ループ再生される前提。最初と最後を黒にして繋ぎ目を自然にする

### タイムライン（確定）

```
0.0-2.5s   タイトルカード   黒地にタイトル（フェードイン→ホールド→アウト）
2.5-7.0s   シーン1（4.5秒） 字幕あり

7.4-11.4s  シーン2（4.0秒） 字幕あり
11.4-14.4s シーン3（3.0秒） 字幕あり ← 後半ほど短くしてテンポを上げる
14.4-14.9s 黒
14.9-18.2s 終盤カード       タイトル ＋ logline
```

### 確定した設計判断

| 項目 | 決定 |
|---|---|
| 字幕の範囲 | **全シーンに出す**（`scenes[].narration`） |
| 尺の配分 | **上記の 4.5 / 4.0 / 3.0 秒で固定。AIの `duration` は編集に使わない** |
| フェード長 | **0.3秒以内**（黒＝消灯なので長いと壊れて見える） |
| テキスト描画 | **`drawtext` の `textfile=` オプションでファイルから読む**（案A）。 |
| | フィルタ文字列に本文を混入させない。加えて制御文字除去・改行除去・文字数上限を実装 |
| | **`drawtext` は自動折り返ししない。日本語は文字数で機械的に改行を挿入すること** |
| 安全マージン | 中心(360,360)、安全半径260px。**テキスト領域 x 200〜520 / y 440〜520**、 |
| | **フォント32px、1行10〜12文字、最大2行**。四隅には何も置かない |
| title / logline | **長すぎるので切り詰める。** 現スキーマは title 100文字 / logline 300文字だが |
| | 画面に出せるのは title 15文字 / logline 40文字程度。 |
| | `generateMovieScript` のプロンプトとzodスキーマの上限を下げるのが根本対処 |
| フォント | **Noto Sans JP Bold（SIL OFL、再配布可）をリポジトリに直接コミット。** |
| | Vercelのlinuxに日本語フォントは存在しない。Boldのみでよい |
| ffmpeg構成 | **単一の `filter_complex` で1パス。** 再エンコードを1回に固定して時間を抑える。 |
| | `-preset veryfast` から開始 |

### ffmpegの骨子

```
-f lavfi -t 2.5 -i color=c=black:s=720x720:r=24    # 冒頭カード用
-i scene1.mp4 -i scene2.mp4 -i scene3.mp4
-f lavfi -t 3.3 -i color=c=black:s=720x720:r=24    # 終盤カード用

filter_complex:
  各シーン: trim → setpts=PTS-STARTPTS → fade(in/out) → drawtext(textfile=...)
  各カード: drawtext(title) → drawtext(logline)
  concat=n=5:v=1:a=0

出力: -an -c:v libx264 -pix_fmt yuv420p -r 24 -video_track_timescale 24000 -movflags +faststart
```

`concat` フィルタは全入力の解像度・pix_fmt・fps・SARの一致が必要。
`prepareHologramVideo` が既に720x720/24fps/yuv420pに揃えているので条件を満たす。
lavfiの黒地側にも同じ指定（`format=yuv420p`, `setsar=1`）を付けること。

# 追記（同日 夕方）: 実測で判明した重要事実と決定

## A. 同梱ffmpegに drawtext が無い【最重要】

`frontend/vendor/ffmpeg/ffmpeg`（johnvansickle製 ffmpeg 7.0.2-static、Vercelにデプロイ済みの実物）は
**`drawtext` フィルタを持っていません**（フィルタ一覧で0件）。

**注意: configure行から推測してはいけません。** この binary の configure には
`--enable-libfreetype` `--enable-fontconfig` `--enable-libfribidi` `--enable-libass` が全て入っていますが、
それでも drawtext は入っていません。一度この推測で誤った判断をしました。
**判断は必ず実際に動かした結果で行うこと。**

また `strings` でフィルタ名を検索する方法も信頼できません（`crop` や `concat` even も検出できない）。

### 検証方法（再現手順）

macOSのローカルffmpeg（Homebrew）にも drawtext はありません。
Vercelと同じ linux/amd64 で検証するには Docker を使います。

```sh
cd ~/Desktop/hackson-no-yatu-deploy/frontend
docker run --rm --platform linux/amd64 -v "$PWD":/app -w /app node:22-bookworm-slim \
  ./vendor/ffmpeg/ffmpeg -hide_banner -filters | grep -c drawtext
```
**`--platform linux/amd64` は必須です。** 省略するとarm64で動き、`resolveFfmpegPath()` が
linux/x64のときだけvendorバイナリを候補に入れる実装のため、そもそも見つかりません。

## B.【決定】drawtext をやめて ass（字幕）フィルタを使う

ユーザー決定。同梱バイナリはそのまま、`composeMovie.ts` のテキスト描画を `ass` に置き換える。

**実物での動作確認済み**: 上と同じコンテナで、同梱バイナリ＋同梱フォントを使い、
`ass=<file>.ass:fontsdir=/app/vendor/fonts` で日本語が正しく描画されることを確認しました。
（`Fontconfig error: Cannot load default config file` という警告は出ますが、描画は成功します）

ass を選ぶ利点:
- デプロイ済みバイナリで動くことが実証済み（バイナリ差し替えの不確実性を回避）
- **中央揃えと折り返しがASSの標準機能**。自前の文字数カウントによる改行挿入が不要になり、
  「字幕が左寄せで2行目が左端に寄る」問題が構造的に解消する
- フェードは `\fad()`、位置は `Alignment` と `MarginV` で表現できる

タイムライン構造（尺配分4.5/4.0/3.0秒、フェード0.3秒以内、安全マージン、黒背景、ループ前提）は
4章の確定仕様をそのまま流用すること。**変わるのは文字を置く手段だけ。**

現在 `8e4a6d1` にコミットされている予告編実装は drawtext 前提なので、**本番では文字が出ません**。
